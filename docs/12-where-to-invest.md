# 新方法该投到哪里：用预测分数找缺口

> 数据：`routed_run`（11,043 条预测分与运行结果）、`hard_solved`、`construction`
> 这些统计由 `routed_run` 与 `hard_solved` 交叉得到，可用 SQL 复算。

## 1. 模型校准

把预测分数分段，看实际解出率：

| 预测 p | 数量 | 实际解出 | 解出率 |
|---|---:|---:|---:|
| [0.0, 0.1) | 5,440 | 127 | 2.3% |
| [0.1, 0.2) | 883 | 143 | 16.2% |
| [0.2, 0.3) | 1,153 | 323 | 28.0% |
| [0.3, 0.5) | 1,557 | 595 | 38.2% |
| [0.5, 0.7) | 1,305 | 725 | 55.6% |
| [0.7, 1.0) | 705 | 584 | **82.8%** |

单调且接近实际频率——分数可以当作"值得试"的概率用。

## 2. 高置信失败：121 条

预测 p ≥ 0.7、但所有方法都没解出。按构造分类：

| 构造 | 数量 |
|---|---:|
| 路径/格路 | 57 |
| 连分数 | 28 |
| cyclotomic | 27 |
| 矩阵 | 5 |
| 三角形/数组 | 4 |

例子：

```
A005221  Number of Dyck paths of knight moves.
A101785  G.f. satisfies: A(x) = 1 + x*A(x)/(1 - x^2*A(x)^2).
A114198  a(n) = Sum_{k=0..n} binomial(n,k)^2*F(k+1).
A188458  Expansion of e.g.f. exp(x)/cosh(2*x).
```

这三个类别（路径、连分数、cyclotomic）里同类序列的 65–86% 能被现有方法解出，
所以模型判断"应该可解"是有道理的。但缺口到底是什么？我做了两个实验：

**(a) 代数生成函数猜测**（P_0 + P_1·A + ... + P_d·A^d = 0，d ≤ 3，deg P ≤ 4，
前 50 项拟合、后 40 项验证残差为零）：只找到 **5 / 121** 条
（A101785、A191586、A109081、A190315、A102403）。代数假设基本不成立。

**(b) 更高阶的 holonomic 搜索**（order ≤5、degree ≤5，用 60 项拟合、30 项验证）：
在剩下的 116 条里又找到 **32 条**。

也就是说：**37 / 121（31%）只是"阶数/窗口不够"，剩下的 84 条才是真正超出这些代数族的。**

这修正了"建一个新方法"的判断——缺口不是一种新方法，而是两件事：

1. **更深、更长的 holonomic 搜索**（机械改进，配合 b-file 的长窗口）；
2. **84 条真正难的**，需要完全不同的思路。

## 3. 高置信跳过但实际可解：335 条

预测 p < 0.25 被跳过，但实际上能被解出。按构造：

| 构造 | 数量 |
|---|---:|
| floor/round | 79 |
| 集合分拆 | 65 |
| 求和/卷积 | 58 |
| 无指纹记录 | 46 |
| 数位/进制 | 17 |
| 分拆 | 15 |
| 数论函数 | 12 |

按真实方法：`pre(2,2)` 76、`bm` 56、`pre(3,2)` 35、`pre(2,1)` 33……

例子：

```
A000246  permutations of odd order        (p=0.07, 实际 pre(2,2))
A025227  a(n) = sum a(i)a(n-i)            (p=0.06, 实际 pre(2,2))
A025707  index of 5^n among 5^i6^j         (p=0.03, 实际 bm)
```

这些是**模型的假阴性**：floor/round 和集合分拆类里有很多其实可被线性递推/P-recursive 解出，
但指纹特征把它们推到了低分区。改进方向是给模型加特征（模周期性、项数、递推阶数）。

## 3.1 长窗口二遍扫描：把"假性硬核"挖出来

对 **702 条 p ≥ 0.5 但没解出**的目标，用 60 项拟合、30 项验证、更高阶模型（order ≤5、degree ≤5）重跑：

- 解出 **216 / 695（31.1%）**；
- 按方法：`long(4,3)` 92、`long(5,4)` 67、`long(5,3)` 39、`bm60` 11、`long(5,2)` 4……
- 单条成本约 **3 秒**（短窗口模型约 0.05–0.3 秒），所以只值得在高置信目标上跑。

随后把这套二遍扫描扩展到 p ∈ [0.25, 0.5) 的 1,525 条（8 个分片中 1 个崩溃，约 194 条未跑）：
又解出 **257 条**。

累计影响：

| | 短窗口（25 项） | + 长窗口二遍 |
|---|---:|---:|
| hard 集解出 | 2,497（22.6%） | **2,970（26.9%）** |
| 候选池失败率 | 61.2% | **57.8%** |

长窗口的收益高度集中在"可构造"的族：生成函数展开 +10.3 个百分点、floor/round +9.9、
路径 +9.8、排列 +8.6、图 +8.5；而素数 +0.4、分拆 0、数论函数 0。

结论：**25 项窗口制造了约 30% 的"假性硬核"**。之前"精确方法饱和在 22.6%"的说法要修正——
饱和点取决于窗口长度，而 b-file 中位数有 1000 项可用。

## 4. 结论与建议

| 投入方向 | 依据 | 预期 |
|---|---|---|
| **长窗口 + 高阶 holonomic 二遍扫描** | 702 条高置信目标里解出 216 条（31.1%） | 已实施，hard 集解出 +216 |
| **改进失败预测特征** | 335 条假阴性集中在 floor_round/集合分拆 | 可把阈值 0.25 的召回从 87% 提到 90%+ |
| 工作点选择 | 阈值 0.15 保留 91.8% 的解、省 72.7% 算力 | 已在 5.5 给出曲线 |
| 代数 GF 猜测 | 只覆盖 5/121 | **不值得作为通用方法** |

还有一个更普遍的教训：**25 项的训练窗口本身限制了可识别性**。
b-file 里中位数 1000 项，用 60 项去拟合高阶递推、再留 30 项验证，是廉价且被验证有效的改进。

一句话：**信号已经足够好到能指出"下一把该磨哪把刀"。**
