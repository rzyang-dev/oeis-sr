# 项目总结：从 OEIS 数据到信号驱动的符号回归

> 从"解析 OEIS"出发，最终得到一个能**判断哪些序列值得试、先试哪个方法**的流程。
> 所有数字都可在本仓库复现。

## 1. 走过的路

| 阶段 | 做了什么 | 主要结论 |
|---|---|---|
| 数据 | 解析 40 万条序列、1783 万项、11 亿 b-file 项 | 格式极干净，0 行异常 |
| 关系 | 四种关系、定义图、恒等式图 | 70,721 条派生、330,004 条原子；31,850 对精确关系无文档 |
| 基准 | v0 闭式基准 + hard track | 闭式基准 96% 可被 BM 解；hard track 失败率 79% |
| 形状 | 16 万条公式的形状清单 | 2,383 种形状，前 100 覆盖 85% |
| 指纹 | 21.8 万条的 b-file 指纹 | 增长类预测可解性（指数 33% vs 其他 4%） |
| 普查 | 18.9 万条精确结构普查 | **77% 非 C-finite** |
| 构造 | 15.5 万条的 26 类构造 | 素数 22%、其他 14.7%、数位 12%… |
| 信号 | 失败预测 + 方法路由 | AUC 0.866；算力 −80%，保留 87% |
| 求解器 | routed.py + 长窗口二遍 | hard 集解出 22.6% → **26.9%** |

## 3. 五个结论

1. **数据不是瓶颈。** 解析、清洗、对齐都很干净；真正的困难在结构。
2. **公式空间高度集中。** 2,383 种形状里前 100 种覆盖 85%——符号回归不该穷举表达式树。
3. **可解性由代数类决定，不由长度决定。** cyclotomic 86%、连分数 77%、
   数论函数 0.9%、分拆 2.5%。长度只是表象。
4. **窗口长度是隐藏变量。** hard track 的 25 项窗口制造了 31% 的"假性硬核"；
   全库普查用 80 项，假象只有 5.8%。任何"可解率"不报告窗口就没有意义。
5. **信号有效，但域特定、必须成本感知。** 为 hard 集调的方法顺序在 easy 基准上
   反而丢掉一半解；加上"先跑便宜的 poly/BM，再路由贵的模型"后，
   基准上召回 99.93%、耗时 −25%，hard 集上仍有 −80% 的算力节省。

## 4. 对符号回归的启示

- **先分类，再路由，最后才拟合。** 生成候选公式之前，先用几百项算指纹、
  判断属不属于可代数求解的族，能省掉大部分无效搜索。
- **多数 OEIS 序列没有低复杂度闭式（约 77%）。** 任何在 OEIS 上的 SR 结果
  都应该按"代数类"分层报告，否则"准确率"没有意义。
- **给更多数据（长窗口）比换方法更便宜有效**，但只对"可构造"的族有用；
  对素数/分拆类，窗口再长也没用。
- **关系图是尚未利用的特征来源**：48% 的 hard 公式引用其他序列，
  把父序列的项作为额外输入，是 SR 的下一个自然扩展。

## 5. 已试且为负结果的方向

- **代数生成函数猜测**（P₀+P₁A+…+P_dA^d=0，d≤3）：只覆盖 5/121 高置信失败，
  不值得作为通用方法；
- **父序列多项式**（a = P(b)，deg ≤3，1,829 条有父序列的未解目标）：只解出 **15 条**。
  说明"父序列的项"本身没用——必须知道**算子**（除数和、卷积、前缀和），
  而这需要解析公式文本；
- **二项式变换、归一化（n!、2^n、Catalan）**：抽样命中 <1%；
- **级联**（前缀/差分/仿射）：父序列本身几乎都不可解，收益 0.2%。
