# 数值关系挖掘：OEIS 的"隐蔽派生层"

> 复现：`python scripts/10_numeric_relations.py` + `python scripts/11_verify_numeric.py`
> 结果：`reports/numeric_relations.json`，数据库表 `numeric_relation`。

## 1. 动机

前一步用"名称"建了定义图：330,004 条原子、70,721 条派生。但名称是**文档属性**——
如果两条序列在数值上完全等价，而名字互不提及，它们就会被同时算作原子。

这一步直接问：**用项值本身，能找出多少精确关系？其中多少被文档记录？**

## 2. 方法

对 298,815 条满足"offset ∈ {0,1}、全部项在 int64 内、≥14 项"的序列，用三种 O(N) 检测器：

| 检测器 | 关系 | 候选生成 | 验证 |
|---|---|---|---|
| equal | a(n) = b(n) | 前 14 项哈希 | 全项精确相等 |
| affine | a = α·b + β（α≠0 有理数） | 差分归一化（除以 gcd、定符号）后哈希 | 全项整数交叉相乘精确验证 |
| prefix | a(n) − a(n−1) = b(n) | 差分的 13 项窗口哈希 | 全项精确验证 |

候选对再用 b-file 复核：取**连续 50 项以上**的更长区间重新验证。

## 3. 结果

| | 找到的对数 | 有文档记录 | 无任何记录 |
|---|---:|---:|---:|
| equal | 6,153 | 1,076 | 5,077 |
| affine | 30,117 | 7,561 | 22,556 |
| prefix | 8,551 | 4,334 | 4,217 |
| **合计** | **44,821** | **12,971** | **31,850** |

"有记录"= 出现在 `definition` / `identity` / `xref` 任一处；只看前两者（真正的定义/恒等式）时，无记录的对数是 **37,484**。

b-file 复核（只统计双方都有 ≥25 项、且 b-file 有 ≥50 个连续公共下标）：

| 关系 | 通过率 |
|---|---:|
| affine | **100%**（76/76） |
| prefix | 73.8%（48/65） |
| equal | **12.9%**（4/31） |

## 4. 三个发现

### 4.1 文档缺口很大

约 **71%** 的精确仿射/前缀关系在 OEIS 的关系字段里没有任何记录。
仿射关系是其中最干净的一类（b-file 复核 100%）：a 与 b 只差一个缩放和一个平移，
但两条序列各自被当成独立条目，名字互不提及。

### 4.2 "原子"被高估

按名称统计的 330,004 个原子里，**23,711 个**落在某个数值等价类中（与至少一条别的序列精确仿射/前缀相关）。
涉及无记录关系的序列共 **16,150 条**（占合格集合的 5.4%）。

把仿射+前缀关系做并查集：29,965 条序列塌缩成 **11,169 个等价类**（9,014 个二元类，最大类 828 个成员）。

最大的类暴露了一类退化情形：形如 `(c, 0, 0, 0, …)` 的序列彼此都仿射等价（n≥1 时全为 0），
所以 828 个成员里绝大多数只是"首项不同的终零序列"。这类等价在数学上成立但没有信息量，统计时需要单独说明。

### 4.3 "前 40 项相同"是个陷阱

equal 检测器找到 6,153 对"前 14 项完全相同的序列"，但在 b-file 上只有 **12.9%** 继续保持相同。
典型例子：

```
A182855  Numbers that require exactly five iterations ... 
A392926  Numbers that are neither squarefree nor squareful ...
         → 前 184 项完全一致，n=185 处开始分叉（1248 vs 1248, 1272 vs 1260）
```

这不是重复条目，而是**两种不同刻画在很长一段上恰好一致**。
对做 benchmark 的启示：不能用"项值相同"来判定重复，也不能把 %S 的全部项当作训练集而不留外部验证——
必须用 b-file 或程序生成更远的项。

## 5. 例子

| 关系 | 序列 A | 序列 B |
|---|---|---|
| affine | A272298 `n^4 + 324` | A219056 `3n^4`（a = b/3 + 324） |
| affine | A169024 / A169168 | 同一 Coxeter 群的两种参数化，数值完全相同 |
| prefix | A400770 `Sum_{k=0..n} mu(k^2+k+1)` | A400769 `mu(n^2+n+1)`（前者是后者的前缀和，名字里互相没提） |
| equal→diverges | A182855 | A392926（n=185 处分叉） |

## 6. 对符号回归意味着什么

1. **算子词表有了真实频率**：仿射 30,117 对、前缀和 8,551 对、相等 6,153 对——这三类就占了精确关系的大头。
   它们正好对应"逐点仿射"和"序列级前缀和"两种胶水，和之前的分析一致。
2. **骨架检测器有了训练集**：31,850 条无记录关系 + 12,971 条有记录关系，可以拿来训练/评估
   "给定两条序列的项值，判断它们是什么关系"的排序器。这正是之前缺的那块拼图。
3. **benchmark 必须先做去重**：如果训练集里混入仿射等价的序列，模型会学到"抄近路"。
   用 `numeric_relation` 表做等价类，可以把 298,815 条压到约 287k 条独立序列。
4. **前缀和关系不是 EML 能表达的**（它需要跨下标求和），这再次说明"原子 + EML"必须配一个序列算子层。

## 7. 局限

- 只覆盖 offset ∈ {0,1}、int64 内、≥14 项的序列（约 75% 的库）。
- 仿射检测包含退化族（终零序列），最大类 828 个成员不能直接当作"828 条独立序列被重复"。
- prefix 的 26% 失败可能来自"差一个常数"或起始项例外，需要更宽的模板（a(n)−a(n−1) = b(n)+c）。
- "无文档记录"只针对 `%N/%F/%C` 与 `%Y` 三个来源，不排除在其他字段（如 `%D`、`%H`）里提过。
