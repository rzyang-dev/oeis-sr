# 公式空间的形状结构

> 产物：`reports/formula_shapes.json`、`reports/shape_difficulty.json`
> 复现：`python scripts/27_formula_shapes.py`、`python scripts/28_shape_difficulty.py`

## 1. 问题

符号回归的搜索空间是"所有表达式树"。OEIS 的 54 万行公式如果高度重复，
那正确的策略就不是穷举树，而是**先选形状、再拟合参数**。

形状定义为（主导构造 + 特征集合）：

- 主导构造：`sum` / `prod` / `scaled`（数字系数开头）/ `ref`（以另一条序列开头）/
  `pow` / `fraction` / `other`；
- 特征：是否含 `Sum_`、`binomial`、`!`、`^`、`/`、`sqrt`、`floor`、`log`、
  其他序列编号、`k`、prime、partition 等。

## 2. 分布：高度集中

对 160,833 行以 `a(n) =` 开头的公式统计：

| 前 K 种形状 | 覆盖率 |
|---|---:|
| 10 | 57.2% |
| 50 | 77.8% |
| 100 | 84.9% |
| 500 | 96.7% |

总共只有 2,383 种形状。主导构造的占比：

| 构造 | 占比 |
|---|---:|
| 以另一条序列开头（`a(n) = A012345(...)`） | 31.5% |
| 数字系数开头（`a(n) = 3*n^2 + ...`） | 25.7% |
| 幂型 | 15.9% |
| 求和型 `Sum_{` | 11.9% |
| 分式 | 5.2% |
| 乘积型 | 0.7% |

## 3. 形状决定可解性

把形状与 `hard_solved`（11,043 条 hard 目标的精确求解结果）对齐：

| 主导构造 | 解出率 |
|---|---:|
| `scaled` | **56.9%** |
| `other` | 33.7% |
| `fraction` | 22.8% |
| `pow` | 21.1% |
| `sum` | 19.2% |
| `ref` | 17.9% |
| `prod` | 4.3% |

具体到特征组合，差异更极端（样本 ≥100 条）：

| 形状 | 解出率 |
|---|---:|
| `sum + binom, div, floor, k, pow, sum` | **62.9%** |
| `sum + binom, div, k, pow, sum` | 59.7% |
| `sum + binom, k, pow, sum` | 56.4% |
| `sum + k, pow, ref, sum` | 26.0% |
| `sum + ref, sum` | **2.7%** |
| `sum + div, ref, sum` | **0.2%** |
| `fraction + div, k, ref, sum` | **0.0%** |

规律很清楚：**带 `binomial` + 幂的求和形状是 P-recursive 的主场；
带"其他序列引用"或"求和里套分式"的形状，精确方法几乎碰不到。**

## 4. hard 目标按形状可解性分层

| 所在形状的历史解出率 | 目标数 | 占比 |
|---|---:|---:|
| 0% | 855 | 9.6% |
| 0–5% | 2,303 | 25.9% |
| 5–20% | 2,317 | 26.0% |
| 20–40% | 1,507 | 16.9% |
| 40%+ | 1,918 | 21.6% |

也就是说：**36% 的 hard 目标落在"历史解出率 ≤5%"的形状里**，
再怎么堆精确方法也是白费；而 22% 落在高可解形状里，值得优先投入。

## 5. 对符号回归的启示

1. **形状优先（shape-first）**：不要枚举表达式树，枚举几百种形状，每种只拟合少量参数。
   按覆盖率，前 100 种形状已经覆盖 85% 的公式。
2. **形状可作搜索的剪枝先验**：`ref` 型（31.5%）和 `sum+div` 型在当前方法下解出率接近 0，
   与其花算力，不如先跳过或换表示。
3. **`binom+pow` 是甜点区**：P-recursive 在这里成功率 50–63%，是"值得做"的目标。

## 6. 下一步

- **从项值预测形状**：用增长阶、比值、差分等特征训练一个分类器，
  预测目标属于哪一类形状（C-finite / P-recursive / 求和型 / 引用型），
  从而在求解前就知道该选哪条路。
- **形状驱动的求解器**：为前 50 种形状各写一个参数化模板，
  用项值拟合参数并做留出验证——这是"避免穷举"的直接实现。
