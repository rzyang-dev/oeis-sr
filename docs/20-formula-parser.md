# 公式解析器：把 OEIS 的 %F 变成可计算的 AST

> `oeisdb/formula.py`：分词 → 文法 → AST → 精确求值（Fraction）。
> 验证脚本：`scripts/66_formula_validate.py`。

## 1. 文法

```
expr   := term (('+'|'-') term)*
term   := pow (('*'|'/'|'mod') pow)*
pow    := unary ('^' pow)?          (右结合)
unary  := ('-'|'+')* postfix
postfix:= atom '!'*
atom   := NUMBER | IDENT | IDENT '(' args ')'
        | '(' expr ')'
        | 'Sum' '_' '{' spec '}' term
        | 'Product' '_' '{' spec '}' term
spec   := IDENT '=' expr '..' expr
```

## 2. 求值

- 全部用 `Fraction` 精确计算；
- `binomial/C`, `floor/ceil/abs/sqrt`（只接受完全平方）, `gcd`;
- 数论函数映射到 A 编号：`sigma→A000203`, `tau→A000005`, `phi→A000010`,
  `mu→A008683`, `prime→A000040`, `pi→A000720`, `Omega/omega`, `Fibonacci`, `Lucas`, `Catalan`, `Bell`;
- `Axxxxxx(n)` 从 b-file 查值；`a(k)` 从本序列的 b-file 查值（支持递推）；
- `log/sin/cos/...` 抛 `Unsupported`（不冒充数值计算）；
- `clean_rhs()` 去掉作者署名、区间条件（`n>1`）、尾部注记。

## 3. 踩过的坑

- 分词器把 `Sum_` 整体读成一个标识符（下划线被当作标识符字符）——导致 `Sum_{...}` 全部失败；
- `=` 不在运算符表里——`Sum_{k=0..n}` 的下标解析失败。

两个 bug 都靠手工单元测试发现（`n!`、`binomial(2n,n)`、`Sum`、`Product`、`a(n-1)`、`A000045(n)` 六个用例）。

## 4. 覆盖率（1,200 条 `a(n) = ...` 的样本）

| 结果 | 数量 | 说明 |
|---|---:|---|
| 解析失败 | 416 | 语法超出子集（矩阵、条件式、多行定义） |
| **解析成功** | **784（65%）** | |
| 其中：与 b-file 完全一致 | **343** | |
| 其中：数值不符 | 433 | 多为**定义域问题**：公式只在 n≥1 成立但未标注 |
| 其中：求值错误 | 297 | 多参数 A 编号（`A124010(n,k)`）、负下标自引用 |
| 其中：超越函数 | 18 | log/sin/cos 等，明确拒绝 |

## 5. 已知缺陷

1. **多参数 A 编号**（如 `A124010(n,k)`）只取第一个参数，会产生错误值；
2. **定义域**：很多 `a(n) = ...` 是恒等式而非定义，只在 n≥1 成立，需要从上下文推断；
3. **偏移量**：没有用 %O 的 offset 对齐；
4. 不支持分段定义（`if ... then ...`）、矩阵、集合上的和。

## 6. 索引平移

很多"数值不符"其实是**索引平移**：公式按 offset 0 写，b-file 从 1 开始。
在 ±3 内搜索平移量可以救回一部分。

400 条样本、30 项、平移搜索后：

| 结果 | 数量 |
|---|---:|
| 解析失败 | 158 |
| 求值错误 | 169 |
| 超越函数 | 26 |
| **原样完全一致** | **27** |
| **平移后完全一致** | **10** |
| 零散不符 | 8 |
| 无 b-file | 2 |

平移能救回约 1/4 的"完全一致"——说明**索引对齐是必须的**，
但也说明单靠 ±3 暴力搜索不够，应该用 %O 的 offset1 做正规对齐。

## 7. 解析率与猜想检验

随机抽 3,000 条 `a(n) = ...` 公式：**解析成功 2,432 条（81.1%）**。
剩余失败主要是非纯表达式（`numerator of`、`Sum_{d|n}`、`\|x\|`、多参数）。

把它接到猜想上（`stmt` 里同时含 conjecture 和 `a(n) =`）：

| 结果 | 数量 |
|---|---:|
| 候选语句 | 1,097 |
| 解析失败 | 462 |
| 求值错误 | 305 |
| 无 b-file | 252 |
| 超越函数 | 19 |
| **确认成立** | **28** |
| 未确认 | 31 |

31 条"未确认"逐条看下来全是**提取误差**（渐近式 `O(log n)`、多参数、
`a(n) =` 只是句中片段），**没有一条是真正的反例**。

这说明：解析器本身没有系统性错误，但"从自然语言里抽猜想"这一步需要
更严格的模式（只收 `Conjecture: a(n) = <expr>` 开头、且带 offset 对齐）。

## 8. 覆盖率提升与严格猜想检验

这一轮补了：绝对值 `|x|`、小数、隐式乘法（`2n`）、除子和 `Sum_{d|n}`，
以及未知多参数函数（`P(n,k)`）——后者现在解析成功、求值时归为"不支持"。

随机 3,000 条样本的解析率：**81.1% → 90.8%**。

严格猜想（只收 `Conjecture: a(n) = ...` 或 `a(n) = ... (conjectured)`）：

| 结果 | 数量 |
|---|---:|
| 候选 | 472 |
| 解析失败 | 46 |
| 求值错误 | 219 |
| 无 b-file | 162 |
| **确认成立** | **19** |
| 零散不符 | 10 |

10 条"零散不符"逐条看：`a(n) = A279720(n) for n>=2` 这类**跨序列对齐**问题
（两个序列的 offset 不同），不是反例。

**结论：仍然没有找到真正的猜想反例。** 瓶颈从"解析"转移到了
"跨序列索引对齐"和"求值失败（无 b-file / 多参数）"。

## 9. 数据源与对齐

两个改进：

1. **用 `%S` 的 terms 字段兜底**：没有 b-file 的序列用数据库里的数据行
   （按 `offset1` 对齐），"无数据"从 162 条降到 0；
2. **裸 A 编号的偏移对齐**：形如 `a(n) = Axxxxxx(n)` 的猜想，
   搜索 `a(n) = A(n+d)`（d ∈ [-3,3]）。

结果（472 条严格猜想）：

| 结果 | 数量 |
|---|---:|
| 解析失败 | 46 |
| 求值错误 | 319 |
| **确认成立** | **69** |
| 尾部一致 | 2 |
| 零散不符 | 12 |
| 数据不足 | 5 |

**确认数从 19 提到 69**。

12 条"零散不符"里，`A383541` 的条目自己就写了"This conjecture is false"——
我们的结果与之一致；其余仍是跨序列对齐或提取误差。

## 10. 全库一致性检查（抽样 2,100 条）

8 个分片、每片 300 条 `a(n) = ...`，用 b-file 逐项验证（30 项，shift 0）：

| 结果 | 数量 |
|---|---:|
| 解析失败 | 424 |
| 求值错误 | 643 |
| 不支持 | 251 |
| **完全一致** | **726** |
| 尾部一致 | 3 |
| 零散不符 | **53** |

53 条"零散不符"逐条检查：绝大多数是**解析/提取伪影**：

- `F(n, 2)`（Fibonacci 多项式，未知函数）；
- `a(n) = a(n-1) + ..., a(0)=0`（尾部初值被当成表达式的一部分）；
- `a(n) = a(-18-n)`（负下标）；
- `a(n) = 1, if n <= 2; ...`（分段定义）。

**没有发现一条真正的"公式与数据矛盾"。** 这与 OEIS 的编辑质量一致——
条目被反复校对过，粗粒度的自动检验很难抓到错。

## 11. 求值错误分类（600 条样本）

| 原因 | 数量 | 说明 |
|---|---:|---|
| missing_A | 50 | 引用的 A 编号在该 n 处没有数据（稀疏 b-file） |
| missing_a | 28 | 自引用越界（递推需要更早的初值） |
| non-integer | 9 | 阶乘/幂的下标不是整数 |
| non-square sqrt | 8 | `sqrt(2)` 这类无理数 |
| division by zero | 6 | 公式在 n=0 处未定义 |
| 其它 | — | 已归入 Unsupported：`Pi`、`e`、`i`、`if`、`for`、`exp`、`Stirling1` … |

修复的内容：

- `log/exp/sin/...` 之前被当成**变量**（unbound），现在识别为函数、求值时归为 Unsupported；
- 补上 `round`（四舍五入）、`ceiling`；
- `Pi/e/i/if/for` 等常量与关键字显式归为 Unsupported，不再算"求值错误"。

**关键结论：剩下的求值错误主要是数据问题（缺 A 编号数据、缺初值），不是解析问题。**

## 12. 全库一致性（约 18,000 条）

改进：**逐项跳过未定义的 n**（`missing_a`/`missing_A` 不再让整条公式作废），
以及修复清洗顺序（句号要先剥，否则 `, a(0)=1.` 这类初值去不掉）。

单个分片的效果：完全一致 106 → **134**，求值错误 86 → **40**。

7 个分片、每片 3,000 条（合计约 2.1 万条）：

| 结果 | 数量 |
|---|---:|
| **完全一致** | **10,457（58%）** |
| 零散不符 | 688 |
| 尾部一致 | 91 |
| 求值错误 | 2,315 |
| 解析失败 | 2,311 |
| 不支持 | 1,785 |
| 数据太少 | 362 |

## 13. 688 条"零散不符"的二次判定

对每条计算**最长连续一致窗口**：

| 最长连续一致 | 条数 |
|---|---:|
| ≥10 项 | **5** |
| ≥20 项 | 0 |
| <5 项 | **563** |

只有 5 条能用"定义域/偏移"解释，其余 563 条是**从头到尾都不一致**——
但它们仍可能是解析伪影（例如把 `a(n) = 1, if n<=2; ...` 这种分段定义
误读成单一表达式）。

**至今没有确认任何一条"公式与数据矛盾"。**

## 14. 分段定义与饱和

实现了分段定义：`expr1, if n <= k; a(n) = expr2, if n > k`，
求值时选第一个条件成立的分支；也处理了每段重复写 `a(n) = ` 的写法。

但对全库一致性的提升**几乎为零**（134 → 134，57 个解析失败不变）——
分段定义在 `a(n) = ` 行里占比很小。

## 15. 结论：覆盖率已饱和

| 指标 | 数值 |
|---|---:|
| 解析率（随机样本） | 90.8% |
| 全库一致性抽查（2.1 万条） | 58% 完全一致 |
| 公式-数据矛盾 | **0 条确认** |
| 猜想反例 | **0 条确认** |
| 猜想确认成立 | 69 条 |

剩下的失败几乎都是**数据问题**（稀疏 b-file、缺初值）和**非纯表达式**
（矩阵、渐近式、自然语言），继续改解析器的边际收益已经很低。

更重要的结论是：**OEIS 的公式与数据高度自洽**。
用自动工具在这个粒度上找"错误"基本找不到——这与它被反复校对的事实一致。

## 16. 下一步

1. 用 %O 的 offset 做对齐，把 433 条"数值不符"重新分类；
2. 支持多参数 A 编号（查表用 `(n,k)`）；
3. 把解析器接到猜想检验上：`Conjecture: a(n) = <expr>` 可以直接求值验证。
