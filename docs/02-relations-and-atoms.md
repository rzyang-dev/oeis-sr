## 1. 能提取出四类关系，语义强度完全不同

| 关系 | 来源 | 规模 | 语义 | 适合做什么 |
|---|---|---|---|---|
| 交叉引用 | `%Y` | 1,487,362 条边 / 318,386 条序列 | 弱："see also" | 检索、聚类 |
| **定义** | `%N` 名称 | **87,078 条边 / 70,721 条序列** | 强："用另一条序列定义" | **原子性分析** |
| 恒等式 | `%F`、`%C` | 195,088 条边 / 87,085 条序列 | 中："可以表示为" | 找相关序列、公式迁移 |
| 链接 | `%H` | 601,746 个 URL | 无 | 出处、外部数据 |

关键区别可以用 τ(n) 说明：

- `A000005` 的名称是 "d(n) ... the number of divisors of n" ——**没有引用任何其他序列**，所以它是原子；
- 但它的公式里有 `a(n) = A001227(n)*(A007814(n)+1)` ——这是**恒等式**，不是定义。

如果直接拿"所有提到别的序列的行"当依赖，τ(n) 会被误判成"派生"；只有名称才能代表"这条序列是如何被引入的"。

## 6. "原子"到底该怎么理解

这里采用的是**表述原子性**：一条序列的名称没有借助其他序列的项。它是"文档属性"，不是数学本质：

1. **反驳不了的原子**：名称自足且没有等价物（如 A000040 素数）。
2. **形式上的原子**：名称自足，但数学上显然可以由别人表达（如"a(n) = n^2 + 1"——n^2 不是 OEIS 序列）。
3. **被掩盖的派生**：名称自足，但真正的定义藏在公式里（我们按名称判定，会把这类算成原子）。

反过来，**派生也可能只是注记**：有些名称写成 `floor((3/2)^k) = A002379(k)`，那个 A 编号只是给公式里的表达式一个"身份证"，并不是真的依赖。抽样 30 条定义边人工核对，约 85% 是真依赖；剩下的是这类注记、以及"Duplicate of"（已按等价物降级）。

因此更准确的表述是：**在 OEIS 的记录方式下，82.4% 的序列没有"用别的序列定义"这一层依赖；其中只有 2 万个被真正当作积木使用**。

## 7. 怎么用

```sql
-- 一条序列是不是原子
SELECT NOT EXISTS (SELECT 1 FROM definition WHERE aid = 'A000045');

-- 它用到了谁（定义层面）
SELECT dst FROM definition WHERE aid = 'A336158';   -- A046523, A000265

-- 谁用到了它
SELECT aid FROM definition WHERE dst = 'A000045' LIMIT 10;

-- 传递依赖：A 的最终原子
WITH RECURSIVE dep(x) AS (
  SELECT dst FROM definition WHERE aid = 'A179773'
  UNION
  SELECT d.dst FROM definition d JOIN dep ON d.aid = dep.x
)
SELECT DISTINCT x FROM dep WHERE x NOT IN (SELECT aid FROM definition);
```

```python
import sqlite3
con = sqlite3.connect("oeis.db")
parents = [r[0] for r in con.execute(
    "SELECT dst FROM definition WHERE aid = 'A064076'")]   # ['A064077']
```

## 8. 下一步可以做什么

1. **数值验证定义边**：对 `a(n) = ...` 形式的定义写一个小求值器，用项值验证"父序列 → 子序列"是否真的成立（能同时过滤掉注记型误判）。
2. **找未声明的数值关系**：用项值搜索"a 是 b 的平移/倍数/差分"，可以发现 OEIS 没有记录的关系——这类序列在我们的定义图里会被误判为原子。
3. **给符号回归加特征**：派生序列的父序列项值可以作为额外输入特征。对 70,721 条派生序列，这等于白送一组"相关变量"，可能显著改变回归难度。
4. **原子性作为难度标签**：假设"— 直接由已知原子组合而成的序列，符号回归应该更容易；验证这个假设本身就是一个实验。
