# 论文笔记：All elementary functions from a single binary operator

> Odrzywołek, arXiv:2603.21852v2（2026-04）。原文 PDF 在工作区，抽取的纯文本见
> `reports/paper.txt`。

## 1. 论文做了什么

发现一个二元算子

    eml(x, y) = exp(x) - ln(y)

配上常数 1，就能生成"科学计算器"的全部 36 个原语（π、e、i、四则运算、三角/双曲/反函数、
幂、对数……）。它是连续数学里的 NAND（Sheffer stroke）。作者用"逐个删原语 + 数值反推"
的方式系统性搜索得到，并给出构造性验证。

关键结构：任何初等函数表达式都变成**同构二叉树**，文法只有一条

    S -> 1 | eml(S, S)

## 2. 为什么这和符号回归有关

因为树形固定，可以把"结构搜索"变成"参数优化"。第 4.3 节的 master formula：

- 每个 eml 的输入槽写成 `α + βx + γf` 的线性混合，其中 f 是前一个 eml 的输出；
- α、β、γ 取 (1,0,0)/(0,1,0)/(0,0,1) 时分别退化成常数 1、输入 x、复用子表达式；
- level-n 全树有 `5·2^n − 6` 个参数（level 2 = 14，level 3 = 34，level 4 = 74）。

训练流程（论文原话）：

1. 用 Adam 做普通梯度下降；
2. "hardening"：把权重往 0/1 推；
3. 取整到精确符号值（snap）；
4. 成功时 MSE ~1e-32，即机器精度平方，等价于精确恢复公式。

这就是"D 用 EML 树 + Adam 做符号回归"，不是比喻。

## 3. 论文报告的结果（重要）

- depth 2：随机初始化 **100%** 恢复；
- depth 3–4：约 **25%**；
- depth 5：**<1%**；
- depth 6：448 次尝试 **0 成功**。
- 但**从正确的树加高斯噪声出发**，depth 5–6 也能 100% 收敛回精确值。

结论：**表达力不是瓶颈，找盆地才是**。随机初始化在浅层好用，深层需要更好的初始化/优化。

其他工程细节：必须用复数（complex128）；嵌套 exp 会溢出，log 有分支切割，需要 clamp 和
特殊浮点语义（ln 0 = -∞）。

## 4. 各基本运算在 EML 里的长度（RPN 指令数 K）

| 表达式 | 编译器 | 直接搜索 |
|---|---:|---:|
| e^x | 3 | 3 |
| ln x | 7 | 7 |
| x - y | 11 | 11 |
| x + y | 27 | 19 |
| x^2 | 75 | 17 |
| x*y | 41 | 17 |
| x/y | 105 | 17 |
| sqrt(2) | 165 | >47 |
| i | 131 | >55 |
| π | 193 | >53 |

**这张表很关键**：连乘法和平方都要 K≈17，π 要 193。depth≤4 的树只能装下极短的表达式。

## 5. 和 OEIS 的契合度

### 能对上的部分

- OEIS 有 4,057 条"纯算术闭式"序列（公式只含数字、n、+ − × / ^），其中 3,304 条有 ≥20 项、
  2,543 条同时有 b-file——天然的训练/外推切分。
- 整数项值是天然的精确验证器：snap 之后逐项相等，比 MSE 严格。

### 对不上的部分（必须先想清楚）

1. **EML 只管初等函数**。OEIS 大量序列是阶乘、二项式系数、分拆数、素数、递推计数——
   需要 Γ 或求和，不在初等函数类里。
2. **常数很贵**。含 π、φ、√2 的闭式在 EML 里长度爆炸，depth 4 根本到不了。
3. **数据稀疏**。论文用稠密实数训练；OEIS 只有整数 n 的 0..40 项（b-file 可扩到上千），
   约束弱，容易拟合出"在 0..40 上对、往外就错"的公式——所以必须用 b-file 外推验证。
4. **分段定义**。OEIS 常见 a(0) 特例、n≥1 分支，EML 是单一表达式，难以精确表达分段。
5. **溢出**。2^n 之类在 n 大时嵌套 exp 直接爆掉。

## 6. 可行的实验设计（由小到大）

**E1 复现（1–2 天）**：numpy 实现 level-2/3 master formula（14/34 参数），
用有限差分或手写反向传播求梯度，复现"depth 2 全中、depth 3 约 1/4"。

**E2 OEIS pilot（1 周）**：挑 30–50 条短闭式序列（如 `a(n)=2^n`、`a(n)=4n^2+2n`、
`a(n)=(n^2+n+2)/2`），前 20 项训练、b-file 后段验证，报告 snap 成功率 vs 公式复杂度。

**E3 基准化**：给每条序列估一个"EML 长度"（用编译器或代理指标），画
"可恢复性 vs EML 长度"曲线——这才是论文缺的那张图。

**E4 用 OEIS 当初始化**：论文说从正确树加噪声能 100% 收敛。那 OEIS 的公式表正好可以
当"近似正确的起点"：把公式编译成 EML 树 → 加噪 → 训练 → 看能否 snap 回精确式。
这可能是比"从零训练"更有希望的方向。

## 7. 我的判断

- 用户直觉正确：EML + Adam 就是论文第 4.3 节，且论文把它定位为"可行性证明"，不是终点。
- OEIS 的价值不在"更多数据"，而在**难度分层和精确验证**：它有大量已知答案、有 b-file
  外推、有公式长度分布，可以把"梯度符号回归到底能走多深"量化出来。
- 最大的风险是 depth 墙：直接拿 OEIS 闭式跑 depth 4，大概率大面积失败。所以第一步应该
  先复现 + 测深度边界，而不是直接上全量。
