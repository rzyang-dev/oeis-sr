# Hard track：真正的难度在组合结构里

> 产物：`hard_bench` 表（14,019 条）、`reports/hard_track.json`
> 复现：`python scripts/21_hard_track.py`（约 4 分钟）

## 1. 为什么需要它

v0 基准的 2,891 条闭式序列里，96% 是 C-finite——一个 Berlekamp–Massey 就解决了。
那个基准是"地板"，不是挑战。真正的难度应该来自：

- 含二项式系数、阶乘、求和的公式；
- 需要用到另一条序列（"Sum_{d|n} μ(d)·A000011(n/d)"）；
- 非 C-finite 的增长（指数塔、超指数）。

## 2. 选取方法

从 `%F` 中筛出以 `a(n) =` 开头、且含 `binomial(`、`!` 或 `Sum_{` 的行，
要求序列 ≥20 项且带 b-file。每个序列保留最短的一条作为 ground truth。

| 家族 | 候选序列 |
|---|---:|
| sum | 7,975 |
| binomial | 4,163 |
| factorial | 1,881 |
| **合计** | **14,019** |

## 3. 基线失败率

用与 v0 相同的两个精确基线（degree ≤12 多项式、order ≤12 线性递推），
前 20 项训练、后 30 项（b-file）精确匹配：

| 家族 | hard（两个基线都失败） | 失败率 |
|---|---:|---:|
| factorial | 1,737 / 1,881 | **92.3%** |
| sum | 6,236 / 7,975 | 78.2% |
| binomial | 3,099 / 4,163 | 74.4% |
| **合计** | **11,072 / 14,019** | **79.0%** |

对比 v0 的 4%——同样的基线，在 hard track 上失败率从 4% 跳到 79%。
**难度确实来自公式的代数类，而不是公式长度。**

## 3.1 第二层：P-recursive 猜想器

第一层（多项式 + 线性递推）失败率 79%。第二层针对阶乘/二项式这类 holonomic 序列：
假设

    a(n) = sum_{i=0..r} P_i(n) * a(n-i),   deg P_i <= d

用前 25 项、有理数精确线性代数解出系数（r ≤ 4，d ≤ 4），再在后 30 项上验证。

| 指标 | 数值 |
|---|---:|
| hard 目标 | 11,072 |
| P-recursive 解出（order ≤4, degree ≤4） | 1,966（17.8%） |
| 扩展到 order ≤6, degree ≤4 后的新增 | **+455** |
| 累计解出（含 poly/BM） | **2,497 / 11,043 = 22.6%** |
| 剩余失败率（相对 14,019 条候选池） | **61.2%**（原 79.0%） |

逐条结果已落库：`hard_solved(aid, method)`，method ∈ {poly, bm, pre(r,d), pre_high(r,d), 空}。
这是后续所有层的统一基线。

再往上加阶数收益迅速衰减：在 500 条残余样本上试 order ≤8、degree ≤6，
只命中 **1.2%**（6/500），不值得全量跑。P-recursive 这一族在 order 6 附近已经饱和。

按模型分布：order 2/degree 1（425）、order 2/degree 2（424）、order 2/degree 3（241）、
order 3/degree 1（203）……说明大多数可解的 hard 目标是低阶 holonomic。

距离 <50% 的阶段目标还差一层。下一层试了**序列算子级联**，结论见 3.2：
它几乎不贡献（2/1,060）。剩下的候选是"组合模板库"（Bell 型二项式卷积、
Catalan 型卷积等），这是下一轮的方向。

## 3.2 第三层：序列算子级联（负结果）

思路：如果 hard 目标 a 是某条序列 b 的前缀和 / 差分 / 仿射变换，而 b 可解，那么 a 也可解。

- 1,060 条 hard 目标有这类父序列（来自 numeric_relation 与定义文本里的 "partial sums" / "first difference"）。
- 做法：只用 b 在目标训练截止点之前的项拟合 b，外推到目标需要的区间，再套算子。
- 结果：不加校验时解出 6 条；加上"用 b 已知的最后 5 项做留出验证"后，**只剩 2 条**。

逐点组合层同样做了：404 条 hard 目标有 `a = b ± c` 或 `b·c` 的分解，
338 条的操作数"可解"——但这是假象（求解器会返回未经校验的外推）；
加留出验证后只有 21 条通过，最终**级联成功 0 条**。

结论：**难度是遗传的**。OEIS 的结构边把 hard 目标连到 hard 目标：
父序列要么本身是组合计数（分拆、素数间隔、图计数），要么我们的求解器
在其已知项的最后 5 项上就已经失败。级联不能降低 hard 子集的失败率。

## 3.3 第四层：组合模板库（增量 ≈ 1 条）

针对组合数学里最常见的几类"非 C-finite"递推，直接在项值上验证：

| 模板 | 形式 | 命中 |
|---|---|---:|
| Bell | `a(n+1) = Sum_{k=0..n} C(n,k) a(k)` | 1（A000110） |
| Catalan 卷积 | `a(n+1) = Sum_{k=0..n} a(k) a(n-k)` | 1（A000108） |
| Motzkin 型 | `a(n+1) = a(n) + Sum a(k)a(n-1-k)` | 4 |

但其中 Catalan、Motzkin 本来就被 P-recursive 层解出，**真正的增量只有 Bell 一条**。
模板只能抓住教科书级的少数序列——残余的 9,000 多条不服从任何已知的短递推模板。

## 4. 这些目标有"结构抓手"吗

对 11,072 条 hard 目标，检查已有的结构资源：

| 资源 | 覆盖 |
|---|---:|
| 精确数值关系（equal/affine/prefix） | 1,307 |
| 逐点分解（a = b ± c / b·c） | 192 |
| 有文档的定义父序列 | 2,274 |
| **以上都没有（"裸"目标）** | **7,720（69.7%）** |

也就是说：**七成的 hard 目标是"裸"的**——没有数值孪生、没有逐点分解、没有文档化的父序列，
只有项值和一条自然语言/数学混排的公式。这才是真正的深水区。

## 5. 硬核长什么样

| 序列 | 公式 | 类型 |
|---|---|---|
| A000110 | `Sum_{k=0..n} Stirling2(n,k)` | Bell 数 |
| A000041 | 分拆数 | 组合计数 |
| A000088 | `2^binomial(n,2)/n! * (...)` | 无标号图 |
| A000166 | `n! * Sum_{i=0..floor(n/3)} (-1)^i/(i!*3^i)` | 错排相关 |
| A000013 | `(1/(2n))·Sum_{k} phi(...)·2^gcd(...)/phi(...)` | Burnside/循环指标 |

它们的共同点：**要么是超指数增长（阶乘、2^(n²)），要么定义依赖另一条序列的项**
（`Sum_{d|n} μ(d)·A000011(n/d)`）。两类都不是"n 的初等函数"，
也都不是 C-finite。

## 6. 对整条路线的含义

1. **OEIS 的公式发现任务有两层**：C-finite 层（可被线性代数秒杀）与组合层（真正的挑战）。
   任何 benchmark 不区分这两层，数字就没有意义。
2. **EML/梯度路线只覆盖第一层的一小块**（逐点初等函数），而且树深远超 4。
3. **真正有希望的方法**必须能处理：
   - 阶乘/二项式（Gamma 结构，P-recursive）；
   - 对另一条序列的求和/卷积（需要"序列算子"）；
   - 循环指标/Burnside 型公式（需要群论模板）。

## 6.1 失败模式：剩下的 8,546 条是什么

| 类别 | 数量 | 占比 |
|---|---:|---:|
| 求和型（`Sum_{...}`） | 3,172 | 37.1% |
| 公式里引用其他序列（`A012345`） | 2,770 | 32.4% |
| 二项式型 | 1,517 | 17.8% |
| 阶乘型 | 821 | 9.6% |
| 素数相关 | 234 | 2.7% |
| 分拆相关 | 29 | 0.3% |
| 其他 | 3 | 0.0% |

**48.1% 的残余公式直接引用了另一条序列**（`Sum_{d|n} A007431(d)`、`2^binomial(n,2)/n!*(...)`）。
这意味着：**在"只看本条序列的项"的设定下，这部分目标在原理上就不可解**——它们的定义需要别的序列。

另一半（求和型、二项式型、素数/分拆型）是真正的组合计数对象：
分拆数、素数计数、图计数、循环指标。它们既不是 C-finite，也不是 holonomic，
没有短的递推模板。

## 6.2 精确方法的天花板

| 方法 | 新增 | 备注 |
|---|---:|---|
| 多项式 + BM（基线） | — | 79% 失败 |
| P-recursive（order ≤6） | +2,497 | 22.6% |
| 序列算子级联 | +2 | 父序列本身不可解 |
| 逐点组合级联 | +0 | 操作数不可解 |
| 组合模板（Bell/Catalan/Motzkin） | +1 | 教科书级 |
| 归一化（n!、2^n、Catalan） | ≈0（1/300 抽样） | |
| 二项式变换后再拟合 | 0/140 抽样 | 变换后也不是 C-finite |
| 更高阶 P-recursive（order ≤8） | ≈1.2%（抽样） | 饱和 |

综合来看：**精确的、只看项值的方法在 hard 集上大约到 23% 就饱和**，
对应的候选池失败率是 61.2%，离 <50% 的目标还差 11 个百分点，
而所有已试方法族的边际收益已经跌到 1% 以下。

## 7. 局限

- ground truth 是公式**文本**，没有解析成 AST；评估用的是项级外推，不是表达式等价。
- "hard" 定义为"degree ≤12 多项式 + order ≤12 递推都失败"，更高的阶数可能仍能解。
- 部分 sum 公式其实是恒等式（形如 `a(n) = A...` 的分解），不一定是"闭式"。
- 未处理 `tabf/tabl` 与多变量序列。

## 8. 下一步

1. **P-recursive 基线**：加一个"多项式系数递推"的猜测器（guess 类算法），看能吃掉多少 hard。
2. **序列算子**：把 prefix、卷积、二项式变换作为显式算子，测它们在 hard 上的覆盖。
3. **表达式级评分**：对能解析的公式做 AST 比较，而不是只比项。
